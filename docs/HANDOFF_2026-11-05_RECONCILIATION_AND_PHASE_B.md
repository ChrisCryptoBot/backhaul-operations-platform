## 8. The reconciliation design to build (approved)

1. **Region layer.** New `Region` (workspace, name, note, archived) and `Terminal.regionId`. Settings gets a Regions tab beside Terminals (admin); Terminals get a Region select. The migration seeds nothing; terminals start unassigned (show an "Unassigned" bucket).
2. **A scope, not a terminal.** `Scope = { regions, terminals }` resolved to a set of terminal names, or `null` for everything. `currentScope()` replaces `currentTerminal()` as the one thing every list asks; `currentTerminal()` stays as a thin wrapper so the ~30 call sites move one screen at a time. Helpers `terminalWhere(field, scope)` (Prisma) and `terminalSqlIn(scope)` (raw SQL); `inTerminal`/`terminalSql` keep the "truck or driver in it, or unplaced" rule extended to a set.
3. **Permission as well as view.** `MemberScope` (member, region or terminal), enforced on the server. `checkAccess` already re-reads the Member each call; `Identity` gains `scope`; `currentScope()` returns the cookie's choice **intersected** with what the person may see. A dispatcher assigned Dallas and Houston cannot see or book Memphis. The Team card in Settings gets the assignment; the demo role buttons get sensible scopes.
4. **Picker.** The header's one-terminal select becomes a Scope menu: All, a region (with its terminals), or several terminals, with driver/truck counts, remembered per person (last scope, never silent All for admins), and the page head always states the scope ("Texas region: 3 terminals, 140 trucks, 160 drivers").
5. **Screens brought into the scope** (each with a test that a scoped request never returns another terminal's rows): KPI (`getDeskKpi` takes the scope, in its cache key; load read, drivers, lanes, customers, trucks, trend, extras), Lanes, Customers, lane detail, header counts, Messages, exports, Quote open pickups, Planner (filter before building rows), Radar loads, Audit and global search.
6. **Quote a load made usable:** page ships only the scope's trucks (or none plus a typed truck search); pricing is **nearest first**: pick the N nearest bases to the pickup inside the scope (haversine, then road for the shortlist), price those with their own deadhead, then rank by margin; default N = 25 with "Show more" (fixes both bugs above); chips for Trailer fits (type and length), On shift, Available (no clash, papers good), Terminal; "Fleet deadhead to pickup" becomes the ten nearest plus a search; unpriced table shows a slice; Assign picker defaults to the scope's home drivers with "Everyone" one click away (still a base, never a fence); copy like "N trucks in scope, showing the best 25 of the nearest 25".
7. **Big lists get searched, not scrolled:** KPI filter dropdowns become type-ahead (top 50 plus search); the driver leaderboard shows top and bottom ten with "All drivers" expanding; Lanes and Customers get server paging and search with the scope applied.
8. **KPI line charts, sexier within the rules** (`components/desk/kpi/trend-grid.tsx`, `trends.tsx` SmallMultiples; `lib/kpi-view.ts:80,100` `sparkPath/sparkPoints`; CSS `.sm-*`/`.kc` in `app/(desk)/desk.css` ~:351, :418-428, :1022-1027). Today: raw SVG 220x56 `preserveAspectRatio="none"`, baseline + one 2px gold straight path, 9px round end dot (legacy 50% radius), hover guide + live dot + shared tooltip. Planned: flat single-token area fill (fill-opacity, no gradient), **square** markers instead of round, dashed ghost line for the prior period on the same scale (`growthOf` data exists), min and max markers with values, 1px gridlines at min/mid/max, end value tagged at the line end with its change (existing DeltaChip), a faint fleet-average rule; keep straight segments (honest for weekly data). Tokens only, no gradients/shadows/blur, no edge strips.

## 9. Phase B (the next code to write): B1 Leak ledger, designed but NOT started

Goal: one weekly **dollar** figure per leak (every sample on the consulting page is a dollar leak), with trend and a drill to the loads behind each line; page `/leaks` and a headline on the KPI. Build it **scope-aware from day one** (argument `scope: string[] | null`, null = everything; reuse `terminalSql`/`inTerminal`), pure math in `src/lib/leaks.ts`, server read in `src/server/tl/leaks.ts`, screen under `app/(desk)/leaks/`, nav entry, role gate (`requireCan` like the KPI), CSV export, tests. Suggested leak lines and where each input already exists (all verified by reading the code):

- **Empty-mile cost** = empty miles × the truck's cost per mile. Empty miles: `Fact.emptyMiles`/`pickupEmpty`/`returnEmpty` in `server/tl/kpi.ts` (`deadheadMilesOf`, `effectiveMiles`). Cost per mile: the load's frozen `snapshotBaseFloorRpm` (break-even $/driven mile before fuel, frozen at accept; `KpiLoadRow.snapshotBaseFloorRpm`). Loads without a floor: count the miles but leave them unpriced and say so (do not invent a rate).
- **Unbilled detention**: `detentionOfLoad` + `waivedDetentionLoads` in `server/tl/detention.ts`, `summarizeDetention` in `lib/detention.ts` (per-stop grace, truck's rate from frozen `snapshotDetentionRate`/`snapshotFreeGraceMinutes`, `billedExtra` from the invoice's Detention line, `unbilled`, `noRate`). `getDetentionRecovery` reads the last 90 days (`DETENTION_WINDOW_DAYS`) and already filters waived rows out and takes a `terminal`; for the ledger write a sibling that also returns the **waived** dollars (waiver is an audit event `detention_waived` with reason; waived rows currently get `unbilled: 0`) and buckets by `completedAt` week.
- **Trailer dwell owed/waived**: `dwell()` in `lib/telematics.ts` with company terms `dwellFreeHours`/`dwellPerDayRate` (Settings, Rules, `lib/thresholds.ts`) and per-trailer overrides (`dwellRateOverride`, `dwellDaysOverride`, `dwellWaived`); `server/tl/dwell.ts` writes audit actions `dwell_adjusted`/`dwell_waived`/`dwell_reset` with before/after "Owed" strings. Dwell is **current stay only, no history**: show currently-owed dwell on dropped trailers plus waived/adjusted amounts from the audit trail, and say history builds from now.
- **Below-floor shortfall**: `Fact.clearedFloor` rule is `(gross − expenses) / drivenMiles >= snapshotBaseFloorRpm`; shortfall = `floor × drivenMiles − (gross − expenses)` when positive (TONU excluded), per load.
- **TONU not invoiced**: TONU loads have `status = 'tonu'`, `tonuRevenue`, `paymentStatus` null → alert `READY_TO_INVOICE` ("A TONU fee is owed and not invoiced yet", `lib/alerts.ts:272`). Sum `tonuRevenue` where not invoiced; also optionally the TONU trend and "TONU billed vs owed".
- Optional later: **net lane profit** from the frozen floor, fuel and detention (previously noted as "needs cost allocation", but the frozen per-load fields get close; mark it an estimate).
- Output shape suggestion: `LeakLedger = { weeks: [{ weekStart, lines: {key,label,dollars,loads,unpriced}[] , total }], current, prior, byLane/byCustomer/byTruck drill, loads: { key, loadId, loadNumber, dollars }[] }`, computed as a ratio of sums over facts like the KPI does; keep it cached with `answerCache` (key must include the scope and the extras stamp). Perf must stay near today's ~1 s at 1,500 trucks / 50,000 loads (add a scale perf test).
- Wording discipline: every figure labelled with its basis ("at the truck's own floor"), unpriced loads counted separately, no invented numbers.

After B1: **B4 Data health** (completeness score per module; loads missing times/miles/arrival/market rate/driver pay; cross-source checks: fuel-card gallons vs trip fuel, ELD miles vs billed loaded miles, rate confirmation vs invoice; printable as a "Data Readiness" report), **B6 Load-history importer** (CSV/TMS export or weekly-tracker template, column mapping, preview, dedupe; the desk imports trucks/trailers/drivers from CSV already via `lib/import-csv.ts`, not loads), then **B2/B3** (stored signals with first/last seen and status; thresholds in Settings > Rules; notification adapter seam like `server/partners/adapters`: sandbox that records and sends nothing, Slack incoming webhook, email provider, SMS later; secret-guarded `/signals/cron`; weekly report that sends itself). **B3 needs Chris's inputs:** which email provider (Resend/Postmark/SMTP), a Slack webhook URL to test with, and his go to add a Vercel cron (`vercel.json` has no crons today; the pattern exists in `app/(public)/partners/cron`).
