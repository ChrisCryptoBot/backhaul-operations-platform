## 3. What I found reading the code, per item

### 3.1 Time zones

- **The bug, in `apps/web/src/server/ratecon/map.ts`:** a `CENTRAL` state set, `stateOf(address)`, `cityState`, and
  `stopTime(date, time, address)` which builds `new Date(\`${date}T${time}:00${offset}\`)` with a **fixed** `-06:00` for Central states and `-05:00` for everything else. That is CST all year (wrong in daylight time, so every Central stop is an hour off from March to November) and it treats Mountain/Pacific as Eastern. `extractionToLoadDraft(raw)` calls it for each stop's `windowEndTime` / `appointmentTime`. `extractionToLoadDraft` is sync and pure; callers are `server/ratecon/reader.ts` (lines ~29 demo readings and ~42 live).
- **The phone's version** (`C:\Users\14698\OneDrive\Desktop\TRUELANE\lib\rateCon\stopTime.ts`, read-only): exports `zoneForState`, `stateOfAddress`, `zoneAt(lat, lng)` (uses `tz-lookup`), `instantInZone(date, time, zone)`, types `Wall`/`Window`, `windowFromWall(wall, zone)`, `zoneLabel`, `formatInZone`. Imports: `tz-lookup` and `@/lib/appointmentWindow` (`parseOpen24h`, `parseTimed`). `lib/appointmentWindow.ts` (87 lines) has **no imports** of its own, so it vendors cleanly.
- **How the phone uses it:** `lib/rateCon/newLoadFromRateCon.ts` (around lines 140-160 and 260-330): each stop keeps the printed wall time (`appt`), then a zone is attached, `zoneSource: 'coordinates'` when the geocoded point resolved a zone, `'state'` when only the state did, then `windowFromWall(s.appt, zone)` produces the instants. `lib/rateCon/mapToLoadForm.ts` uses `instantInZone` and `zoneLabel`. Read these before deciding how much to mirror.
- **Vendoring checklist:** add `lib/rateCon/stopTime.ts`, `lib/appointmentWindow.ts` and `lib/rateCon/tz-lookup.d.ts` (the phone ships its own `declare module 'tz-lookup'`) to `FILES` in `apps/web/scripts/vendor-truelane.mjs`, then `node scripts/vendor-truelane.mjs` (never hand-edit `src/truelane/**`). Add `"tz-lookup": "6.1.25"` to `apps/web/package.json` (the phone pins `6.1.25`; licence CC0; `tz-lookup` is in the phone's `node_modules` but **not** the desk's), install from the `dispatch-desk` workspace root. Check the desk `tsconfig` picks up the `.d.ts` under `src/truelane`.
- **Suggested shape:** keep `extractionToLoadDraft` pure and sync. Add an async pass in `reader.ts` after the draft is built: geocode each stop address with the **temporary** `geocode` from `server/geo/mapbox.ts` (1-hour memory cache, fails soft; **do not store temporary results**), `zoneAt` the point; fall back to `zoneForState(stateOfAddress(address))`; if neither, fall back to the old Central guess **and mark the stop's zone source as unknown** so the review shows a visible note. Show the zone beside each time in the review (`zoneLabel`). Question for Chris if it matters: the desk shows every time in Dallas time (`lib/zoned.ts`); a stop in Eastern will therefore display one hour earlier than printed on the document everywhere except the review, which should show the stop's own zone. I would show stop-local time in the review and Dallas time elsewhere, and say so in the doc.
- **Tests (pure, no network):** a summer Eastern stop (EDT `-04:00`, which the old guess got wrong), a winter one, a Pacific stop, Arizona (no DST), a Central stop in July (old guess off by an hour), the state fallback, the unknown fallback. Mocked-`fetch` test for the geocode step pinning the URL and the `access_token` param name (never the value).
