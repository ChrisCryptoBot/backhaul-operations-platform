### Gotchas that cost time before (learn from them)

- **Bash tool + heredocs:** a heredoc containing an apostrophe in a prose string can die with `unexpected EOF`. For files with prose, use the **Write tool**. For scripted edits use Python in a quoted heredoc (`<<'EOF'`) or the Edit tool.
- **Backslash-b becomes backspace** in Python heredocs (`\\b` → 0x08). Use `chr(92)` or the Edit tool when you need a backslash in generated code. Also: `\\n` inside a non-raw Python `'''...'''` replacement becomes a real newline in the source; this broke `save.ts` once (fixed). Check generated escapes.
- **ESLint in `src/server/**`** bans `Number()`, `Math.round`, `Math.floor` etc. ("Use Decimal rounding for KPI formulas"). Use `Prisma.Decimal` (`new Prisma.Decimal(x).div(...).floor().toNumber()`, `.toDecimalPlaces(n)`). Pure `src/lib/**` modules may use normal math.
- **`tests/no-legacy.test.ts`** forbids `src/app/api` (route handlers for the desk live outside `/api`, e.g. `src/app/(desk)/geo/suggest/route.ts`) and **pins the Prisma model names**. New *columns* are fine; a new *model* (e.g. the planned `brokers`) requires updating that pin deliberately.
- **Server actions queue**: Next runs server actions one at a time, so anything slow or chatty (geo lookups) is a **route handler**, not a server action, or it blocks Quote's live pricing.
- **Modal focus bug (fixed):** `kit/modal.tsx` re-ran its autofocus effect whenever a caller passed a fresh `onClose`, bouncing focus on every keystroke in dialog forms. It now holds `onClose` in a ref. Don't regress it.
- **Driver payload confidentiality gate:** `dispatchLoad` refuses if the driver-facing payload contains a "secret" value (the rate, fuel surcharge, etc.). A fixture whose driver pay equals the load's fuel surcharge tripped it (`driver payload contains a secret value: 100`). When writing tests, don't make the driver's dollars equal the surcharge/rate.
- **Double-booking guard:** `assignDriver` refuses a driver already on another open load in an overlapping window. Test fixtures that assign the same driver need **different days** per load.
- **Browser pane:** screenshots from the pane are small (about 320 wide even when the viewport is emulated at 1440); rely on `read_page`, `find`, `javascript_tool` DOM probes and `get_page_text` more than screenshots. A screenshot taken right after typing can lag: re-read the DOM before retyping or values double. `form_input` fills selects fine; for text boxes use `triple_click` + `type`. `find` sometimes returns "No matches" right after navigation/opening a dialog; call it again. Refs go stale after re-render. Use `resize_window` with 1440x900 and 1024x768 for the two checks, then `preset: desktop` to clear.
- **Toasts** pause on hover and leave after ~6 s (8 s minimum with an action); the delete Undo toast is set to 20 s.
- **`form_input`-style React text boxes:** don't use it on controlled text inputs (state may not update).

## 4. Architecture you need to know

**Stack:** Next.js 14 App Router, React 18, TypeScript strict, Prisma 6.19 + Postgres, vitest 3, ESLint with project restrictions. No Tailwind: plain CSS in `apps/web/src/app/globals.css` and `apps/web/src/app/(desk)/desk.css` using `--db-*` tokens, two themes (night and "manila" day), density cookie.

**Layers**
- `src/lib/*`: **pure** modules (validation, formatting, rules). Both client and server import them; tested without a DB. Examples: `quote.ts`, `load-edit.ts`, `company.ts`, `pay.ts`, `pay-method.ts`, `geo.ts`, `planner.ts`, `disruptions.ts`, `invoicing.ts`, `audit-diff.ts`, `settlement.ts`.
- `src/server/tl/*`: the **domain/DB layer** (Prisma). `quote.ts` (fit table, save/book), `dispatch.ts` (assign/send/unassign, double-booking guard, confidentiality gate), `edit.ts` (load edit), `remove.ts` (delete/restore), `invoicing.ts`, `settlement.ts`, `company.ts`, `snapshot.ts` (freeze cost floor), `evaluate.ts` (calls the vendored `evaluateLoad`; `driveHoursFor`), `queries.ts` (board rows, load detail), `planner.ts`, `kpi.ts`, `alerts.ts`, `audit.ts` (`recordAudit`, always inside the same transaction as the change).
- `src/server/ratecon/*`: `reader.ts` (Anthropic), `map.ts` (extraction → draft), `save.ts` (reviewed draft → load).
- `src/server/geo/*`: Mapbox (see below).
- `src/app/(desk)/actions.ts`: all **server actions** (thin wrappers that call the domain layer, then `revalidatePath`). Pattern: action returns a result object; the client shows toast/inline errors.
- `src/app/(desk)/**/page.tsx`: pages (server components); `src/components/desk/*`: UI (many client components); `components/desk/kit/*` primitives (Modal, Toast, icons, states).
- `src/truelane/**` is **vendored from the phone repo and must never be hand-edited.** Regenerate with `node scripts/vendor-truelane.mjs` (reads `TRUELANE_ROOT`, default the phone repo path). See `src/truelane/VENDORED.md`. If the desk needs another phone module, add it to `FILES` in the script and re-run it. Vendored pieces the desk uses: `evaluateLoad`, `calculators`, `tripHours` (`driveHoursForAllMiles`), `costProfileSnapshot`, `fuelSurcharge`, `fuelPriceForRates`, `rateCon/*`, `trailerData`, etc.

**Conventions that matter**
- **Audit everything:** a change writes an `AuditEvent` in the same transaction (entity, action, summary, before/after, optional reason). Adding an action means adding it to `ACTION_LABEL`, `ACTION_TONE` and `AUDIT_GROUPS` in `lib/audit-diff.ts` (a test checks this).
- **Soft delete:** `Load.deletedAt`. Nearly every query already filters `deletedAt: null`; **saved quotes are loads with `status = "quote"`**, kept out of every list by the `notQuote` predicate. Always include both filters in new queries.
- **Snapshot:** `freezeLoadSnapshot` writes the truck's cost floor etc. onto the load at booking/assign so later profile edits never rewrite an agreed load. Once-only fields are written only when empty; pass `refresh: true` after a truck change.
- **Money rules:** percent-of-rate pay base = agreed rate + fuel surcharge (not detention/extras), 0–99.99, the driver is told the dollars not the rate; flat/hourly pay don't follow rate changes; `payEstimate` is recomputed on an edit only for cpm/percent. Fuel surcharge on a load is stored in **dollars** (`fuelSurcharge`) with the unit (`fuelSurchargeUnit`) remembering how it was typed.
- **Dates:** all human times are **Dallas (Central) time**: `lib/zoned.ts` (`parseCentralLocal`, `toCentralLocal`). Edit forms hold whole minutes; compare times to the minute.
- **Quote form state** (`QuoteValues`) is string-based and has a `manual` set of fields the dispatcher typed: auto-measured values never overwrite typed ones; blanking a field hands it back to the map.
- **Tests:** unit tests in `tests/*.test.ts`; DB tests in `tests/integration/tl-wave*.integration.test.ts` guarded by `describe.skipIf(!RUN_DB_INTEGRATION)`. They create their own rows with a unique name prefix, assert, and delete everything in `afterAll`. They run serially (`fileParallelism: false`). A new wave adds `tl-waveX.integration.test.ts`.

### Mapbox / geo (Wave B), because it is new

- `lib/geo.ts` (pure): label condensing, route parsing, loaded/empty split (`legKinds`, `splitRouteMiles`, the phone's rule: a leg is empty only from a delivery to a pickup), `METERS_TO_MILES`.
- `server/geo/mapbox.ts`: the only door to Mapbox; token server-side; **temporary** geocoding for suggestions/measuring (nothing stored), **permanent** geocoding (`mapbox.places-permanent`) only to store coordinates; everything fails soft; 1-hour in-memory cache for measuring.
- Route handlers (outside `/api`): `GET /geo/suggest?q=` and `POST /geo/measure`.
- `components/desk/address-input.tsx`: ARIA combobox; the suggestion list is **portalled to `document.body`** with fixed positioning and flips upward near the bottom (so dialogs never clip it).
- Stop `lat/lng` are saved after a booked quote, a saved rate-con, and a load edit (`server/geo/persist.ts`), never failing the save.
- `loads.estimated_loaded_hours` holds measured drive hours; `driveHoursFor` spreads them over all miles (fallback 50 mph).

## 7. Per-wave procedure (do this every time)

1. **Plan the wave** with a task list; read the relevant existing code first (the codebase has strong conventions; follow them).
2. **Build** — pure logic in `src/lib`, DB logic in `src/server/tl`, a server action in `actions.ts`, UI in `components/desk`. Audit every state change. Honour the locks (invoiced / on a statement / started).
3. **Tests** — unit tests for pure logic; an integration test file for DB behaviour (own rows, unique prefix, cleanup, different days per assigned driver); regression tests for any bug you find.
4. **Gates:** `tsc`, eslint (`--max-warnings=0`), full vitest with `RUN_DB_INTEGRATION=true`. All must be green.
5. **Walk it in the browser** at **1440 and 1024** (night; day too when the wave touches styling). Check for horizontal overflow (`document.documentElement.scrollWidth > innerWidth`), keyboard operation of new controls, console errors. Keep the pane visible for Chris.
