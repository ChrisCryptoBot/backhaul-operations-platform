## 3. What the tracker import is

- Pure `lib/tracker-import.ts`: `WEEK_FIELDS`, `autoWeekMap`/`cleanWeekMap`/`missingWeekFields` (a lane is one column, or a pickup and a delivery column), `checkWeekRows` (week is any day, counted Monday to Sunday via `mondayOf`; lane split on "to" or an arrow and spelled "City, ST → City, ST"; empty miles as a total or before plus after; duplicates by week+lane against the table and within the file; future weeks refused), `weeksOf`/`lanesOf` (per loaded mile, empty share over every mile driven).
- Server `server/tl/tracker-import.ts`: `previewHistoryImport`, `commitHistoryImport` (one transaction, workspace lock, duplicate check again under the lock, 500-row chunks, ONE audit event with the batch id in `entityId`, a fully raced second click writes nothing), `listHistoryImports`, `removeHistoryImport` (deletes the batch's rows outright; they are copies of a spreadsheet), `getImportedHistory`.
- Table `imported_history` (workspace, batch, `week_start` DATE, lane, loads, line_haul, fuel_surcharge, loaded_miles, empty_miles, source). It **never becomes loads** and nothing built from loads (KPI, Lanes, Customers, Leak ledger, Data health) reads it. The "Imported history" card on `/kpi` is shown only to people who can see every terminal (`currentAllowed() == null`), because history belongs to no terminal.
- Actions `previewHistoryImportAction`, `commitHistoryImportAction`, `removeHistoryImportAction` need `dispatch` (in `tests/loads-roles.test.ts`).
- The running dev server needs its Prisma client reloaded after a schema change: `prisma generate` fails with EPERM while the dev server holds the engine (the types still update); touch `apps/web/next.config.mjs` to reload (never kill processes).
